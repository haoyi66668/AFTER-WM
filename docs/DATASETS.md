# Datasets

Six prediction datasets, the test files of ESCP-HC beyond its training range, and the start conditions of the control task. Every data folder has a card in `datasets/cards/` with its generation protocol, arrays, files and sha256. The datasheet is [data/README.md](../data/README.md).

| Dataset | Folder | Kind | Sequences per split | Used in the paper for | Card |
|---|---|---|---|---|---|
| JSHC (Joint-Switch HalfCheetah) | `data/jshc/` | simulated; change protocol of GrBAL and MBCD, generated by us | 288 / 144 / 144 / 144 | prediction (Table 1, Fig. 1b, 3, 6, 7), queries without a change (Table 2), models of the control task | [jshc.md](../datasets/cards/jshc.md) |
| ESCP-HC | `data/escphc/` | simulated; change schedule of ESCP, generated by us | 288 / 144 / 144 / 144 | prediction (Table 1, Fig. 3, 6, 7), queries without a change (Table 2) | [escphc.md](../datasets/cards/escphc.md) |
| ESCP-HC beyond the training range | `data/escphc_beyond/` | simulated; factors 1.5^u with u ~ U(-4, 4) | test files only: 144 / 144 | changes beyond the training range (Table 2) | [escphc_beyond.md](../datasets/cards/escphc_beyond.md) |
| Panda | `data/panda/` | simulated, built by us | 288 / 144 / 144 / 144 | prediction (Table 1, Fig. 1b, 3, 6, 7), robot-arm examples (Fig. 4), queries without a change (Table 2) | [panda.md](../datasets/cards/panda.md) |
| UR5e | `data/ur5e/` | simulated, built by us | 288 / 144 / 144 / 144 | prediction (Table 1, Fig. 1b, 3, 6, 7), robot-arm examples (Fig. 4), queries without a change (Table 2) | [ur5e.md](../datasets/cards/ur5e.md) |
| Hopper | `data/hopper/` | simulated, built by us | 288 / 144 / 144 / 144 | prediction (Table 1, Fig. 1b, 3, 6, 7), queries without a change (Table 2) | [hopper.md](../datasets/cards/hopper.md) |
| ALFA | `data/alfa/` | sequences derived from real fixed-wing UAV flights | 240 / 86 / 100 / 122 | prediction on real flights (Table 2) | [alfa.md](../datasets/cards/alfa.md) |
| Control episodes | `data/control_episodes/` | simulated start conditions | 48 test episodes | control task (Table 2) | [control_episodes.md](../datasets/cards/control_episodes.md) |

Splits are TRAIN / VAL / TEST / TEST_B (the paper's TE-B); groups of sequences (the sequences of one simulated parent or of one real flight) never cross splits. The paper uses TEST and TEST_B together as the test set.

## Sequences and queries

All sequences have 301 states and 300 transitions at dt = 0.05 s. A query uses a 64-step context and the 40 following actions and states (a 2 s horizon); queries start at steps 64, 96, 128, 160 and 192 of every test sequence (5 queries per sequence). Models read only `obs` and `act`; every other array (physical parameters, change times, failure labels) is an analysis label and is never given to any model. Of the settings of Fig. 7b, the one with a context of 128 steps uses only the query starts 128, 160 and 192 (`configs/arms.json`).

## Analysis labels

`datasets/labels.py` computes, from the label arrays of the test files, the change phases (steps since the latest change), the queries without a change in context or horizon, the queries with transient disturbances (friction or motor-strength pulses or impacts) but no change, and the queries beyond the training range. The labels behind the stored outputs are in `outputs/labels/`:

```
python datasets/labels.py --data-root data --out OUT_DIR
```

## Checking and regenerating

```
sha256sum -c datasets/SHA256SUMS
python datasets/check_data.py --data data
bash datasets/regenerate_all.sh OUT_DIR [jshc escphc escphc_beyond panda ur5e hopper control_episodes alfa]
```

`datasets/check_data.py` compares every array (dtype, shape and sha256 of the bytes) with `datasets/ARRAY_SHA256.json`. `datasets/regenerate_all.sh` runs the unit tests of the simulated generators, regenerates the requested datasets and ends with the same check. Use the generation environment (`environment/requirements-generate.txt`; Python 3.11, numpy 2.1.2, MuJoCo 3.11.0, Gymnasium 1.3.0). In our runs every regenerated file was byte-identical with the pinned packages on Linux x86-64; on a CPU with AVX-512 this was shown only with AVX-512 switched off in NumPy (`NPY_DISABLE_CPU_FEATURES`, `OPENBLAS_CORETYPE=Haswell`). On other systems `datasets/check_data.py` compares the arrays.

- Panda and UR5e need the MuJoCo Menagerie models: `bash datasets/assets/fetch_menagerie.sh`.
- ALFA needs the original archive: `bash datasets/alfa/download_alfa.sh` (or place the archive processed.zip in `datasets/alfa/` by hand).
- The control episodes are built with the code of the control task (`control/`), which `datasets/regenerate_all.sh` finds in the repository root.

The random draws of each simulated dataset are seeded from a namespace string and the position of the draw (see the cards). These strings are fixed identifiers (`docs/FIXED_IDENTIFIERS.md`); changing one changes every random draw.
