# ESCP-HC: sudden-change HalfCheetah

Simulated data generated by us (`datasets/escphc/`). The change schedule is a port of the "sudden change" environment of ESCP (Luo et al., AAAI 2022; MIT licence, see `THIRD_PARTY_NOTICES.md`).
The torso-mass parameter is defined as in DORA (Zhang et al., ICML 2024).

## Content

- Simulator: Gymnasium 1.3.0 `HalfCheetah-v5`, MuJoCo 3.11.0, frame skip 5, dt = 0.05 s, reset noise 0.1.
- Tasks: each task sets three factors at once, for torso mass, joint damping and gravity, each `1.5 ** u` with `u ~ U(-3, 3)` (only the vertical gravity component matters). One seeded generator draws 40 training tasks and 40 held-out tasks. TRAIN sequences use the training tasks; VAL, TEST and TEST_B use the held-out tasks, each with its own sequences (start states, task lists and action plans).
- Schedule (ESCP): a 16-entry task list (start task + 15 tasks drawn uniformly with replacement); the task changes every 100 steps from reset. Each sequence records 300 transitions that start at a random offset 0-99 after reset, so every sequence contains three scheduled task boundaries; a boundary can keep the same task (`chg_eff`).
- Actions: the open-loop plan generator of JSHC (four kinds cycling over sequences, limit 0.95, low-amplitude steps 110-139 and 230-254); no feedback.

## Arrays (N sequences)

| key | dtype, shape | meaning |
|---|---|---|
| `obs` | float32 [N, 301, 17] | HalfCheetah-v5 observation |
| `act` | float32 [N, 300, 6] | actions |
| `mass_mult`, `damp_mult`, `grav_mult` | float32 [N, 300] | factors in force at each transition |
| `grav_z` | float32 [N, 300] | vertical gravity (m/s^2) |
| `task_id`, `list_index` | int16 / int8 [N, 300] | task and task-list entry at each transition |
| `task_list` | int16 [N, 16] | the task list of the episode |
| `offset` | int16 [N] | start of the recorded transitions after reset |
| `chg_state`, `chg_eff` | int16 / bool [N, 3] | state index of each scheduled boundary inside the sequence; whether the task changes there |
| `eval_starts` | int16 [5] | query starts 64, 96, 128, 160, 192 |
| `since_group` | int8 [N, 5] | change phase G1-G5 of each query start (see below) |
| `since_steps`, `chg_k` | int16 [N, 5] | steps since the latest change (-1 none); step of the earliest change inside the 40 predicted steps (-1 none) |
| `pool`, `kind`, `plan_seed`, `reset_seed`, `parent`, `cohort`, `sequence` | [N] | task pool, action kind, seeds and ids |

Change phases (paper supplement, Sec. C.2): G1 = a change inside the 40 predicted steps at step 20 or earlier; G2 = a change inside the 40 predicted steps after step 20; otherwise G3 = 0-15, G4 = 16-63, G5 = at least 64 steps since the latest change or no change.

## Generation

Environment as for JSHC. `bash datasets/regenerate_all.sh OUT escphc` runs the unit tests and `python -B -m escphc.cli collect --out OUT/escphc --log-scale-limit 3` (from `datasets/`).
Seeds are derived from a fixed namespace string (`NAMESPACE` in `datasets/escphc/gen.py`) and the position of the draw.
The namespace string is a fixed identifier (`docs/FIXED_IDENTIFIERS.md`); changing it changes every random draw.
