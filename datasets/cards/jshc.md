# JSHC: Joint-Switch HalfCheetah

Simulated data generated by us (`datasets/jshc/`, shared core `datasets/simcore/`). The change protocol follows GrBAL (Nagabandi et al., ICLR 2019) and the switching schedule of MBCD (Alegre et al., AAMAS 2021); only the protocol was re-implemented, no code of these projects is included.

## Content

- Simulator: Gymnasium 1.3.0 `HalfCheetah-v5`, MuJoCo 3.11.0, frame skip 5, dt = 0.05 s.
- Change: at every transition exactly one of the five leg joints bshin, bfoot, fthigh, fshin, ffoot (action indices 1-5) has no power: its commanded action component is set to 0 before the simulator step. Each sequence draws a phase uniformly from 0-99; the joint without power is drawn at the start and redrawn every 100 steps from that phase on, each draw uniform over the five joints. A redraw can repeat the previous joint, so `changed` marks actual changes only.
- Actions: open-loop plans of four kinds (smooth AR(1), piecewise constant, periodic, i.i.d.), limit 0.95, scaled by 0.15 in steps 110-139 and 230-254; no feedback. The stored action is the commanded action before the power of the joint is removed.
- Start states: reached after 16-80 roll-in steps from reset, with a contact-state quota (stable / transition / airborne = 60 / 20 / 20 %).
- Structure: parent (start state) -> 2 cohorts (action plans) -> 6 sequences `d0`-`d5`, each with its own joint schedule.

## Arrays (N sequences)

| key | dtype, shape | meaning |
|---|---|---|
| `obs` | float32 [N, 301, 17] | HalfCheetah-v5 observation: torso height, pitch, 6 joint angles, 9 velocities |
| `act` | float32 [N, 300, 6] | commanded joint torques (normalized) |
| `fail_joint` | int8 [N, 300] | index of the joint without power at each transition (1-5) |
| `changed` | int8 [N, 300] | 1 where `fail_joint` differs from the previous transition |
| `phase` | int16 [N] | phase (0-99) of the 100-step switching clock |
| `parent`, `cohort`, `sequence` | str / int8 / str [N] | parent id, cohort (0, 1), sequence id (`d0`-`d5`) |

## Generation

Environment: Python 3.11, numpy 2.1.2, mujoco 3.11.0, gymnasium 1.3.0 (`environment/requirements-generate.txt`). `bash datasets/regenerate_all.sh OUT jshc` runs the unit tests and

```
cd datasets
python -B -m jshc.cli collect --counts train=24,val=12,test=12 --seed-offset 0 --workers 4 --out OUT/work/jshc/main
python -B -m jshc.cli collect --counts test=12 --seed-offset 1 --workers 2 --out OUT/work/jshc/testB
python -B -m jshc.cli assemble --main OUT/work/jshc/main --testb OUT/work/jshc/testB --out OUT/jshc
```

All random draws are seeded from sha256 of a namespace string and the position of the draw.
The namespace string is the constant `NAMESPACE` in `datasets/jshc/config.py`.
The namespace string is a fixed identifier (`docs/FIXED_IDENTIFIERS.md`); changing it changes every random draw.
