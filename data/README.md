# Datasheet of the datasets

Version 1.0. This file describes the data in this folder. The cards in `datasets/cards/` give the generation protocol, the arrays and the sha256 of every file; `docs/DATASETS.md` gives the commands.

## Motivation

The datasets contain sudden, persistent changes in robot dynamics, with known change times and physical parameters. They were made to test the multi-step prediction of world models when the robot dynamics change during interaction. Three datasets are new (Panda, UR5e, Hopper). Two follow established change protocols and were generated by us (JSHC, ESCP-HC). One consists of real flights (ALFA: sequences derived from the ALFA dataset).

## Composition

Every file is a NumPy archive with one array per key. Every sequence has 301 states (`obs`) and 300 transitions (`act`). A query is a 64-step context plus the 40 following actions and states; queries start at steps 64, 96, 128, 160 and 192 of every test sequence. The splits are TRAIN, VAL, TEST and TEST_B (the paper's TE-B); the paper uses TEST and TEST_B together as the test set.

| Dataset | Robot model | State (dimension: order) | Action (dimension: order) | Sequences TRAIN / VAL / TEST / TEST_B | Bytes of the data folder | Test queries |
|---|---|---|---|---|---|---|
| JSHC | HalfCheetah (Gymnasium `HalfCheetah-v5`) | 17: torso height, pitch, 6 joint angles, 9 velocities | 6: joint torques | 288 / 144 / 144 / 144 | 14,025,317 | 1,440 |
| ESCP-HC | HalfCheetah (Gymnasium `HalfCheetah-v5`) | 17: as JSHC | 6: joint torques | 288 / 144 / 144 / 144 | 24,201,632 | 1,440 |
| Panda | Franka Panda (MuJoCo Menagerie), payload body at the tool point | 14: 7 joint angles, 7 joint velocities | 7: compliant joint-servo targets | 288 / 144 / 144 / 144 | 8,540,148 | 1,440 |
| UR5e | UR5e (MuJoCo Menagerie), payload body at the flange | 12: 6 joint angles, 6 joint velocities | 6: compliant joint-servo targets | 288 / 144 / 144 / 144 | 7,244,120 | 1,440 |
| Hopper | Hopper (Gymnasium `Hopper-v5` model), joint position servos | 11: torso height, pitch, 3 joint angles, 6 velocities | 3: joint-servo targets | 288 / 144 / 144 / 144 | 6,422,643 | 1,440 |
| ALFA | fixed-wing UAV of the ALFA flights | 12: `gbx`, `gby`, `sin_yaw`, `cos_yaw`, `p`, `q`, `r`, `vN`, `vE`, `vD`, `h`, `airspeed` | 3: `roll_cmd`, `pitch_cmd`, `airspeed_cmd` | 240 / 86 / 100 / 122 | 10,607,244 | 1,110 |

The ALFA sequences come from 12 / 5 / 7 / 7 flights. Two more folders are used for evaluation only: `data/escphc_beyond/` (144 / 144 test sequences of ESCP-HC beyond the training range, 9,682,408 bytes) and `data/control_episodes/` (48 test episodes of the control task, 364,164 bytes). All eight folders together hold 27 files and 81,087,676 bytes.

Models read only `obs` and `act`. Every other array is an analysis label and is never given to any model. Not recorded: images, contact forces and rewards.

### Counts, each with its rule

- Panda, UR5e, Hopper: transitions at which a persistent parameter value (`friction`, `gain` or `payload`) differs from the previous step: 768 / 384 / 384 / 384 per split in each of the three datasets. Of these, 192 / 96 / 96 / 96 lie in `drift` sequences (the change at step 40 and three later steps of slow drift per sequence) and are counted separately.
- JSHC: transitions at which the joint without power changes (`changed` is 1): 708 / 342 / 342 / 341 per split.
- Transitions inside a friction or motor-strength pulse (`friction_eff` differs from `friction`, or `gain_eff` from `gain`): Panda 13,026 / 7,020 / 6,576 / 6,774; UR5e 13,320 / 5,826 / 7,134 / 6,252; Hopper 19,781 / 10,160 / 9,991 / 9,665.
- Transitions that carry an impact (`impulse` is not zero): Panda 2,538 / 1,236 / 1,146 / 1,140; UR5e 2,544 / 1,188 / 1,338 / 1,170; Hopper 2,490 / 1,140 / 1,080 / 1,158.
- Transitions inside a tool-force pulse (`wrench` is not zero): Panda 7,464 / 3,366 / 3,138 / 3,690; UR5e 7,410 / 3,852 / 2,628 / 3,342.

The paper's analyses around a change use the subset of isolated changes defined in its supplement.

### Notes for users

- On Panda, UR5e and Hopper the ranges stated in the cards are sampling ranges. In `drift` sequences the values are clipped at payload [0, 3] kg (Panda) and [0, 5] kg (UR5e), motor strength [0.7, 1.3] (Panda, UR5e) and [0.5, 1.5] (Hopper), and torso mass [1, 3] (Hopper). The data contain payloads up to 3.0 kg (Panda) and 5.0 kg (UR5e), and on Hopper a motor strength up to 1.5 and a torso mass up to ×3.0.
- On Panda, UR5e and Hopper, TEST_B is generated with another seed offset and reuses the parent names of TEST; use (split, parent) as the group key.
- On Hopper the array `payload` holds the torso-mass factor.

## Collection

The simulated sequences were generated in MuJoCo with open-loop action plans: the actions do not depend on the state. Start states are reached after a number of simulated steps from reset (see the cards). On the two arms a plan is drawn again when a sequence makes the arm touch itself or the floor, or reach a joint limit. On Hopper a plan is drawn again when a sequence fails the health check of the generator (`health_check` in `datasets/hopper/gen.py`). The ALFA sequences are cut from recorded flights with a closed-loop autopilot; their actions are the commanded roll, pitch and airspeed.

## Splits

Groups of sequences never cross splits: the sequences of one parent on the simulated datasets, and the sequences of one flight on ALFA, always fall into the same split.

## Labels

`datasets/labels.py` computes the labels of the test queries from the label arrays:

- change phases: the steps from the latest change to the prediction start (ESCP-HC stores its own phases in `since_group`);
- queries without a change in the context or horizon;
- queries with transient disturbances but no change (Panda, UR5e, Hopper);
- queries beyond the training range (`data/escphc_beyond/`).

Pulses and impacts do not count as changes. The number of queries with each label is in `outputs/labels/LABEL_COUNTS.json`.

## Uses

The data are meant for multi-step prediction under changing robot dynamics and for research on dynamics adaptation. No rewards are stored. All datasets except ALFA are simulated, and their actions are open-loop plans. The ALFA sequences were placed without using the failure labels.

## Regeneration

In our runs every regenerated file was byte-identical with the pinned packages on Linux x86-64; on a CPU with AVX-512 this was shown only with AVX-512 switched off in NumPy (`NPY_DISABLE_CPU_FEATURES`, `OPENBLAS_CORETYPE=Haswell`). On other systems `datasets/check_data.py` compares the arrays.

## Loading example

Run it from the repository root. It loads one dataset, cuts one query and normalises it with the mean and standard deviation of the training file. The pipeline does the same in `pipeline/data.py`.

```python
import numpy as np

train = np.load("data/panda/panda_train.npz", allow_pickle=False)
test = np.load("data/panda/panda_test.npz", allow_pickle=False)
obs, act = test["obs"], test["act"]
print(obs.shape, act.shape)
flat_obs = train["obs"].reshape(-1, obs.shape[-1]).astype(np.float64)
flat_act = train["act"].reshape(-1, act.shape[-1]).astype(np.float64)
obs_mean, obs_std = flat_obs.mean(0), np.maximum(flat_obs.std(0), 1e-6)
act_mean, act_std = flat_act.mean(0), np.maximum(flat_act.std(0), 1e-6)
sequence, start, context, horizon = 0, 64, 64, 40
ctx_obs = (obs[sequence, start - context:start + 1] - obs_mean) / obs_std
ctx_act = (act[sequence, start - context:start] - act_mean) / act_std
fut_act = (act[sequence, start:start + horizon] - act_mean) / act_std
fut_obs = (obs[sequence, start + 1:start + horizon + 1] - obs_mean) / obs_std
print(ctx_obs.shape, ctx_act.shape, fut_act.shape, fut_obs.shape)
```
